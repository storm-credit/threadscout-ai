# Phase 2B Plan — 실용 신박템 프롬프트·스키마·통합 시뮬레이션

## 목표

고정된 여섯 에이전트 각각에 실제 실행 가능한 시스템 프롬프트와 출력 스키마를 부여하고, 실용 신박템 한 개가 오케스트레이터부터 Guardian·사람 승인·로컬 큐까지 통과하는 통합 시뮬레이션을 만든다.

## 성공조건

1. 고정 여섯 에이전트 모두 시스템 프롬프트를 가진다.
2. 프롬프트마다 임무, 입력, 도구, 금지 행동, 중지 조건, JSON 출력 계약이 포함된다.
3. 여섯 산출물 모두 상세 스키마를 가진다.
4. 실용 신박템 점수는 신기함보다 문제 해결·시연·실용성을 우선한다.
5. 신기하지만 효용이 낮은 후보는 추천되지 않는다.
6. 통합 시뮬레이션에서 여섯 에이전트가 각각 한 번 호출된다.
7. 초안은 네 개이며 서로 다른 전략 관점에 연결된다.
8. 가격·재고·판매자·옵션·확인 시각은 Evidence Verifier의 한 증거 패킷에 들어간다.
9. Guardian pass와 사람 승인 전에는 큐를 만들 수 없다.
10. 최종 큐는 로컬 전용이며 외부 게시가 꺼져 있다.

## 중지조건

- 일곱 번째 역할이 필요해짐
- 라이브 API 또는 유료 모델 호출이 필요해짐
- 제품 증거를 실제 사실처럼 가장해야 함
- Guardian 또는 사람 승인 게이트를 우회해야 함
- 테스트 실패를 해결하려면 기존 안전조건을 약화해야 함

## 비목표

- 실제 Threads 검색
- 실제 쿠팡 상품 조회
- 실제 제품 가격 주장
- 라이브 LLM 호출
- 실제 제휴 링크 생성
- 외부 자동 게시
